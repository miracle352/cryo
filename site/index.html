Six walls the docs don't mention.

Freezing a process on a Sprite with CRIU hit six walls. Here is each one, and the way around it. A few of them may be news to Fly too.

depth01

Root can't trace other users

Sprites drop CAP_SYS_PTRACE, so CRIU can't freeze anything the sprite user owns.

agents start as root, the same owner as CRIU
depth02

Time can't be restored

No CAP_SYS_TIME, so restoring a time namespace fails outright.

drop the timens image; the clock just jumps
depth03

File watches can't reopen

No CAP_DAC_READ_SEARCH, so inotify watches can't be reopened by handle. Claude Code watches its settings.

a seccomp filter hides inotify; agents fall back
depth04

The disk lies about devices

On the overlay root, folders report one device and files another, so watched files can't be found. io_uring can't be dumped at all.

the same filter switches off inotify and io_uring
depth05

Restore keeps the boot_id

It restarts the container, not the kernel, so "did we reboot?" says no.

pair boot_id with PID 1's start time
depth06

Timers only tick while awake

A paused Sprite freezes every process, so "every 60 seconds" can mean an hour.

snapshot after real work, measured in CPU time
Bring your own agent

Give yours a second life.

One Python file on top of CRIU and two Sprite services. When an agent comes back, cryo emails you through the Resend connector, and the key never touches the machine.

# on any Sprite sudo apt-get install -y criu tmux git clone https://github.com/miracle352/cryo && cd cryo && sudo ln -sf "$PWD/cryo" /usr/local/bin/cryo sudo env PATH="$PATH" HOME=$HOME IS_SANDBOX=1 cryo run myagent --tmux -- claude sudo env PATH="$PATH" HOME=$HOME cryo install --api # freeze after work, thaw on every boot sudo cryo alerts --email you@example.com # "your agent survived a restart"
