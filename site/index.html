Dive log

How deep we had to go.

Freezing a process on a Sprite hit six walls the docs don't mention. Each one, and the way around it.

depth01

Root can't trace other users' processes

Sprites drop CAP_SYS_PTRACE, so CRIU can't freeze anything owned by the sprite user.

cryo starts every agent as root, the same owner as CRIU
depth02

Time can't be restored

No CAP_SYS_TIME: restoring a time namespace fails with "Unable to set a monotonic clock offset."

cryo drops the timens image; the process just sees its clock jump
depth03

File watches can't be reopened

No CAP_DAC_READ_SEARCH, so CRIU can't reopen inotify watches by handle. Claude Code watches its settings file.

a seccomp filter makes inotify unavailable; agents fall back
depth04

The disk lies about devices

On the overlay root, folders report one device number and files another. Watched files can't even be found by scanning. io_uring can't be dumped at all.

the same filter switches off inotify and io_uring
depth05

A restore keeps the same boot_id

It restarts the container, not the kernel, so the usual "did we reboot?" check says no.

cryo pairs boot_id with the start time of PID 1
depth06

Timers only tick while awake

A paused Sprite freezes every process, so "every 60 seconds" can mean an hour.

cryo snapshots after real work, measured in CPU time
Bring your own agent

Give yours a second life.

One Python file on top of CRIU. Two Sprite services. Alerts through the Resend connector, with the key never on the machine.

# on any Sprite sudo apt-get install -y criu tmux git clone https://github.com/miracle352/cryo && cd cryo && sudo ln -sf "$PWD/cryo" /usr/local/bin/cryo sudo env PATH="$PATH" HOME=$HOME IS_SANDBOX=1 cryo run myagent --tmux -- claude sudo env PATH="$PATH" HOME=$HOME cryo install --api # freeze on activity, thaw on every boot sudo cryo alerts --email you@example.com # "your agent survived a restart"
